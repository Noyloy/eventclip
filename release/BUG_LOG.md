BUG-003 update: root cause is unsignaled AAC-LC encoder priming (~2048 samples / two frames) muxed as content at PTS 0 with no edit list. The product encoder wrapper pads silent PCM through EOS so the delayed tail is flushed, drops the priming frames, and rebases PTS to 0. Output delay/padding stay 0; source gapless rejection of nonzero delay/padding is unchanged. A local software emulator then passed the official decode-gate thresholds (lag 0 ms, voice ratios about 1.00). A later official S23 selected-method run of HELD vc9 also passed the same unchanged thresholds (lag 0 ms, unmarked 1.007, marked 0.993, final 0.996, correlation 0.99983, all windows in range). This is not listening or visual acceptance.
BUG-004 update: default S23 camera stills are often Ultra HDR (gainmap) JPEG or HEIF. The product path now decodes those with ImageDecoder (sRGB target), flattens gain maps, strips motion-photo trailers, and writes a baseline JPEG for export. HEVC video remains rejected. WebP is accepted and transcoded. Mirrored EXIF orientations are baked rather than rejected. A local software emulator imported extensionless MediaStore URIs for JPEG, EXIF-rotated JPEG, motion-photo-style JPEG, PNG, WebP, and a synthetic Ultra HDR gainmap JPEG; a non-decodable HEIF fixture returned HEIC_UNSUPPORTED (not the old video-probe failure). A Birthday export that used an imported photo reached EXPORT_READY and the official decode-gate windows still passed. Real S23 Photo Picker URIs and camera HEIF/Ultra HDR files have not been confirmed on device.

BUG-005 update: a 32 s software-emulator export ran for several minutes with mux progress, so the 21000 ms mux watchdog did not fire as a total timeout. After error propagation, the failure that maps to the generic EXPORT_FAILED copy was AAC_ENCODER_DELAY_PAD_STALLED (ERROR_CODE_FAILED_RUNTIME_CHECK). Official ~9 s decode-gate fixtures never construct a 32 s timeline (the pack song is 12 s) and often still had a free AAC input slot at EOS, so they missed the deadlock. The software AAC encoder’s max-input-size is 4096 bytes (one 1024-sample frame); the 2048-sample pad is now split across Media3 pumps by withholding EOS until the pad is complete, without a blocking second dequeue. A local software emulator then exported a 32 s mixed synthetic project to EXPORT_READY (720×1280 rotation 0, first PTS 0) and the official decode-gate windows still passed at unchanged thresholds (lag 0 ms, voice ratios about 1.00, correlation 0.99983). A later official S23 selected-method run of HELD vc13 also reached EXPORT_READY (720×1280 rotation 0) on a ~32 s mixed synthetic project. This is not listening or visual acceptance.

## Root cause / regression evidence
- After a successful read-only copy from a content URI, still preflight accepted only PNG (8-bit) and JPEG. On API 34+, a gainmap (Ultra HDR) or non-sRGB bitmap was rejected as UNSUPPORTED_MEDIA — the copy shown in the picker review. Any other ISO-BMFF file (HEIF/AVIF included) was treated as an MP4 because the header contains `ftyp`, then failed the H.264 video probe with the same code. WebP had no `ftyp` and was rejected immediately. Picker URIs without a filename extension were not themselves the failure (type comes from bytes after copy; persistable grants are not required because the file is copied immediately).
- Fix: sniff still vs video from magic bytes and brands; decode stills with ImageDecoder (sRGB target) or BitmapFactory; flatten gain maps; bake unusual EXIF; strip motion-photo trailers; write baseline JPEG when needed. HEVC video stays rejected. If a recognized HEIF/AVIF still cannot be decoded on the device, the code is HEIC_UNSUPPORTED with specific EN/HE copy.

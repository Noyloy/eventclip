## Root cause / regression evidence
- The on-screen EXPORT_FAILED copy (“Something went wrong while creating. Your project is saved. Try again.”) maps to job.state EXPORT_FAILED, not the leave-app interrupt string. The 21000 ms Media3 mux watchdog is a no-sample stall detector, not a total elapsed timeout; a 32 s software-emulator export ran for several minutes with mux progress and was not killed at 21 s wall.
- Official short decode-gate fixtures never build a 32 s timeline (song is 12 s; movie ~9 s), so they missed the long-export EOS path. On a 32 s export, a follow-up maybeDequeueInputBuffer at EOS deadlocked (ERROR_CODE_FAILED_RUNTIME_CHECK / AAC_ENCODER_DELAY_PAD_STALLED). The software AAC encoder’s max-input-size is 4096 bytes (one 1024-sample frame), so the 2048-sample pad cannot fit in one codec buffer; ending the stream after a partial pad left official last PTS just outside the 50 ms duration audit.
- Fix: never dequeue from the pad path. Pad as much silence as the current buffer can hold; if pad remains, strip EOS so Media3’s next pump (after a drain) supplies another empty EOS buffer. Growable test buffers still flush in one queue. Codec-backed buffers are not compacted. Priming frames are still dropped and PTS rebased; declared delay/padding stay 0.

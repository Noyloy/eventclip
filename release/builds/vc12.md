## Root cause / regression evidence
- A 32 s selected-method run of HELD vc11 on S23 went PLANNING→EXPORT_FAILED in about one second, before any MP4 was written, with reasonCode empty and error=null. That is the unique signature of ProductExportController's main-thread start() `catch(_:Exception)` calling finish("EXPORT_FAILED") without errorState(). Worker prepare failures and Transformer.onError already recorded a reasonCode. Logcat showed clip AAC and song WAV decoders start and release normally, then no TransformerInternal / ExportException / AndroidRuntime line before the assertion.
- This is not BUG-005 (AAC_ENCODER_DELAY_PAD_STALLED fires at encoder EOS after a long encode). The official ~9 s S23 gate never hit this start-of-export swallow (it reached EXPORTING/READY on vc9). The software emulator's 32 s test also starts successfully, so it cannot catch a hardware-only Transformer.start throw; the new contract test forces the same controller catch by pre-creating the partial output.
- Fix: start() catch calls errorState(); error text always includes the exception class (even when message is null); start() requires have explicit messages; failures are logged as EventClipExport. Settled policies are unchanged.
